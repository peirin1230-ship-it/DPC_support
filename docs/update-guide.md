# DPC検索ツール — データ更新手順書

> **対象**: DPC電子点数表の改定（2年ごと）および月次更新（薬剤・出来高算定コードの追加等）時に `src/data.js` を更新する手順
> **前提**: Node.js v20.11 以上、リポジトリを clone 済み（`npm ci` 実行済み）
> **所要時間目安**: 30分〜1時間（制度の構造変更がない場合）

## 1. 更新が必要になるタイミング

| タイミング | 頻度 | 影響範囲 |
|-----------|------|---------|
| **DPC電子点数表の改定** | 2年に1回（令和8年度 → 令和10年度 …） | 全データ |
| **電子点数表の月次更新** | 随時（厚労省が同じファイル番号または新番号で再公開） | 処置等2の薬剤ダミーコード、出来高算定手術等コード（薬剤・検査）など |
| **薬剤商品名（別名）の追加** | 随時 | `database/drug-aliases.json` のみ |

厚労省の電子点数表は「変更区分」（0: 変更なし / 1: 抹消 / 3: 新規 / 5: 変更 / 9: 廃止）と「有効期間（開始日・終了日）」を持っています。生成スクリプトはこれらを解釈し、**抹消行・基準日時点で失効した行・基準日より後に開始する行を除外**します（`--as-of` で過去時点のデータを再現できます）。

## 2. システム構成の全体像

```
厚生労働省 DPC電子点数表（Excel 1ファイル・19シート）
   例: database/001737745.xlsx（ファイル名は改定・更新ごとに変わる）
         │
         ├── database/drug-aliases.json（薬剤コード → 商品名別名。手動管理）
         ▼
  scripts/generate-data.mjs   ← シート名で自動検出・変換・整合性チェック
         ▼
  src/data.js                 ← export const D = {...}（約1.1MB, 1行）
         ▼
  src/utils.js                ← 検索・計算ロジック（通常変更不要）
  src/components/*.jsx        ← UI（通常変更不要。年度表示は D.meta から自動）
         ▼
  npm run validate:data       ← Excelからの再生成結果と src/data.js の一致検証
  npm test                    ← データ不変条件・ロジックのテスト（tests/*.test.mjs）
  npm run build               ← dist/index.html（単一HTML, 約1.0MB）
```

**重要**: 通常の更新では `database/` のExcel差し替えと `src/data.js` の再生成のみで完了します。ヘッダーの「令和X年度」表示や適用日は `D.meta` から自動で表示されます。

## 3. 更新手順

### Step 1: ソースデータの入手と配置

厚生労働省 → 診療報酬 → DPC制度 → 「DPC電子点数表」から Excel（1ファイル）を入手します。

```bash
# 旧ファイルを削除し、新ファイルを配置（database/ に電子点数表は1つだけにする）
git rm database/001737745.xlsx
cp ~/Downloads/00XXXXXXX.xlsx database/
```

> 複数の電子点数表が `database/` にあると、スクリプトは「分類名称」シートの開始日が最も新しいものを使い、注意を表示します。
> `npm run validate:data` も同じ判定を使いますが、混乱を避けるため旧版は必ず削除してください。

必須シート（番号・空白を除いた名称で検出）: `分類名称`, `病態等分類`, `ＩＣＤ`, `年齢、出生時体重等`, `手術`, `手術・処置等１`, `手術・処置等２`, `定義副傷病名`, `重症度等（ＪＣＳ等）`, `重症度等（手術等）`, `重症度等（重症・軽症）`, `重症度等（脳卒中の発症時期等）`, `診断群分類点数表`, `変換テーブル`。
任意シート: `出来高算定手術等コード`, `CCPM対応`, `ダミーコード一覧`（年度ラベルの取得に使用）。

### Step 2: ドライラン

```bash
node scripts/generate-data.mjs --dry-run
```

- 各シートの行数、有効期間の基準日（as-of）、除外行数、件数サマリー（現行 `src/data.js` との増減）、警告、整合性チェックの結果が表示されます。
- `[ERROR]` が出た場合は Step 4 の内容を確認してください（エラーがあると出力は行われません）。

### Step 3: 生成

```bash
node scripts/generate-data.mjs
```

| オプション | 説明 |
|-----------|------|
| `--file <path>` | Excelを直接指定（省略時は `database/` から自動検出） |
| `--out <path>` | 出力先（デフォルト: `src/data.js`） |
| `--as-of YYYYMMDD` | 有効期間の基準日。省略時はExcel内の最新の開始日・更新日 |
| `--aliases <path>` | 薬剤別名JSON（デフォルト: `database/drug-aliases.json`） |
| `--dry-run` | 出力せず件数・整合性チェックのみ |

### Step 5: 薬剤別名の追加（任意）

新しいダミーコード（一般名）に商品名で検索できるようにするには `database/drug-aliases.json` に追記して再生成します。

```json
{
  "0399": ["ゾキンヴィ"],
  ...
}
```

- 現行の処置等2に存在しないコードは生成時に自動で除外され、`[NOTE]` として表示されます。
- 別名が未登録の4桁コードの件数は生成ログの `D.da` 行に表示されます。

### Step 6: 検証・ビルド

```bash
npm run validate:all     # validate:data → test → build
```

### Step 7: 動作確認

```bash

```

1. ヘッダーの年度・適用日・件数表示が新データになっている
2. 一覧検索: 「肺炎」→ 候補選択 → 検索で結果が表示される（条件ラベル「市中肺炎かつ〜」が出る）
3. 手術検索: 「K552」等で検索 → 結果表示、ドリルダウン動作
4. サジェスト: 手術コード + 入院日数 → ステップ選択 → 候補表示
5. 詳細モーダル: 期間・点数・ICD-10・副傷病ICD・重症度、点数推移グラフ
6. 比較: 2件以上選択 → 比較モーダル
7. 「出来高算定一覧」に新しい薬剤・コードが反映されている

### Step 8: コミット・デプロイ

```bash
git add database/ src/data.js docs/
git commit -m "令和X年度 DPC電子点数表（YYYY-MM-DD更新版）にデータ更新"
git push origin master    # GitHub Pages に自動デプロイ（CIで validate:data / test / build も実行）
```

更新内容は `docs/data-update-YYYY-MM-DD-*.md` として記録することを推奨します（例: [data-update-2026-09-02-r8.md](data-update-2026-09-02-r8.md)）。

## 4. 検証手順

### 4.1 生成スクリプト内蔵チェック（エラー時は出力しない）

- 全DPCが13要素、分類が `D.cls` に存在、コードの桁と手術区分・処置等・副傷病の値が一致
- 包括対象: 期間Ⅰ日数 > 0、Ⅰ ≤ Ⅱ ≤ Ⅲ、期間Ⅰ・Ⅲの点数 > 0。期間Ⅱがあれば点数Ⅱ > 0（期間Ⅱなし＝点数表「-」は d2=d1・点数0）
- 出来高: 日数・点数が全て0
- 分岐のある桁（x以外）に必ずラベルがある、7-8桁目の条件ラベル・14桁目の重症度ラベルがある
- `D.si` のインデックスが `D.sl` の範囲内、全分類に `D.icd`

### 4.2 一致検証

```bash
npm run validate:data
```

`database/` のExcelから一時ファイルへ再生成し、`src/data.js` と全キーを比較します。不一致キーと差分の例を表示します。CI（`.github/workflows/validate-dpc.yml`）でも実行されます。

### 4.3 自動テスト

```bash
npm test
```

| ファイル | 内容 |
|--------|------|
| `tests/data.test.mjs` | データの不変条件（構造・ラベル網羅・フラグ整合・別名の妥当性 等）。特定コードをハードコードしないため改定後もそのまま使える |
| `tests/utils.test.mjs` | 検索（ICD/手術/処置）、97フォールバック、分岐なし分類、期間計算（期間Ⅱなしを含む）、ドリルダウン優先度、副傷病フラグ絞り込み |

## 5. データ構造リファレンス

`src/data.js` は `export const D = {...}` をエクスポートします。

### 5.1 `D.meta`

```javascript
D.meta = { label: "令和8年度", effectiveFrom: "20260601", asOf: "20260813", sourceFile: "001737745.xlsx" }
```

### 5.2 `D.dpc`（DPCコード定義）

```javascript
D.dpc["010020x099x0xx"] = [
  "01", "0020", // [0] MDC, [1] 分類4桁
  "1",          // [2] 包括フラグ（"1"=包括対象, "0"=出来高）
  "99",         // [3] 手術区分（コード9-10桁目。"xx"=手術による分岐なし）
  "x",          // [4] 処置等1（11桁目。"x"=分岐なし）
  "0",          // [5] 処置等2（12桁目）
  "x",          // [6] 副傷病（13桁目）
  2, 7, 30,     // [7-9] 期間Ⅰ/Ⅱ/Ⅲ 日数
  4273, 2463, 2093 // [10-12] 期間Ⅰ/Ⅱ/Ⅲ 点数/日
]
```

- [3]〜[6] は **DPCコードの桁そのまま**です。`x` は「その分岐が存在しない」ことを意味し、検索条件と照合する際は常に一致扱い（`utils.matchVal`）になります。
- 期間Ⅱが存在しないDPC（点数表で「-」）は `[8] = [7]`、`[11] = 0` です。

### 5.3 ラベル辞書 `D.lb`

```javascript
D.lb["050050"] = {
  o: { "02": "経皮的冠動脈形成術等", "97": "その他の手術あり", "99": "なし" },
  "1": { "0": "なし", "1": "あり" },
  "1:02": { "0": "なし、１,２あり" },   // 手術区分02のときだけ異なるラベル（上書き）
  "2": { "0": "なし", "1": "１あり", "2": "２あり" },
  s: { "0": "なし", "1": "あり" },
  v: { "0": "他の病院・診療所の病棟からの転院以外", "1": "…転院" }   // 重症度等（14桁目）
}
```

`utils.getLabel(cls, type, value, surgVal)` は `"1:02"` のような手術区分別キーを優先します。

### 5.4 分岐フラグ `D.br`

```javascript
D.br["050050"] = { "99": { "1": 1, "2": 1, "s": 1 }, "02": { "1": 1, "2": 1 }, "97": {} }
```

DPCコードの桁から導出（桁が `x` でなければ分岐あり）。

### 5.5 手術 `D.si` / `D.sl` / 処置等 `D.p1` `D.p2` `D.pc`

```javascript
D.si["050050"] = { "02": 123, "97": 5, "99": 0 }   // 手術区分 → D.sl のインデックス
D.sl[123] = ["K546", "K5461", "K548-2+K931"]      // "K1+K2" は「＋(and)」の組み合わせ手術
D.sl[0]   = ["KKK0"]                               // 手術なし
D.p2["050050"] = { "1": ["G005", "J0451"], "2": ["J0384"], "3": ["0022"] }  // 相関値 → コード
D.pc["070040"] = { "K037": ["K0741", "K0742", ...] } // 処置等1コード → 組み合わせ条件の手術
```

相関値は base36（1〜9, A=10, B=11 …）。値が大きいほどツリー図で下＝高優先。

### 5.6 定義副傷病 `D.sd`

```javascript
D.sd["110070"] = { "1": { a: ["N130", "D70"], n: ["K560"], s: ["J69$"] } }
//  a: 手術あり・なし共通（フラグ1）, n: 手術なしの場合（フラグ2）, s: 手術ありの場合（フラグ3）
```

`utils.getSubdiagICDs(cls, sdVal, surgVal)` が手術区分（99=手術なし）に応じて絞り込みます。`$` 末尾は前方一致。

### 5.7 重症度 `D.sv` / 条件 `D.pt`

```javascript
D.sv["040080"] = { name: "A-DROP スコア", "0": "A-DROP スコア0", "1": "A-DROP スコア1", ... }
D.pt["040080"] = { "0x": "市中肺炎以外", "10": "1歳未満", "22": "市中肺炎かつ15歳以上65歳未満", ... }
```

- `D.sv` は14桁目で実際に分岐する分類のみ。ラベルは点数表「重症度等」列（無ければ条件シートから生成）。
- `D.pt` はDPCコード7-8桁目ごとの条件ラベル。点数表「傷病名」の括弧内（例: 「肺炎等（市中肺炎かつ75歳以上）」）を採用し、無い場合は病態等分類・年齢等シートから生成。

### 5.8 出来高算定 `D.dk` / `D.dx`、その他

```javascript
D.dk["K014"] = "皮膚移植術（生体・培養）"   // コード付き（手術K・検査D）
D.dx = { dr: ["ペムブロリズマブ（遺伝子組換え）（…に限る。）", ...], pt: ["…短期滞在手術等基本料3…"] }
D.da["0204"] = ["キイトルーダ"]              // 薬剤別名（database/drug-aliases.json 由来）
D.cc["010060xx99x00x"] = "010060xxCCPM01"   // CCPM対応
D.cn["K546"] = "経皮的冠動脈形成術"           // コード名称（手術・処置・薬剤共通、"K1+K2" も含む）
D.icd["071030"] = ["M!!!!", "M0000", ...]   // "M!!!!" = ICDテーブルに個別記載のないMコード
```

## 6. Excelシート → D キー変換仕様

| シート | 使用列 | 生成先 |
|--------|--------|--------|
| 2）分類名称 | MDC, 分類, 名称 | `D.cls` |
| 3）病態等分類 | 対応コード, 年齢, 区分名称 | `D.pt`（点数表の括弧内ラベルが無い場合の補完） |
| 4）ＩＣＤ | MDC, 分類, ICD名称, ICDコード | `D.icd`, `D.icn` |
| 5）年齢、出生時体重等 | 条件区分(1年齢/2JCS/3出生時体重/4Burn Index/5GAF/6月齢/7妊娠週数/8分娩時出血量), 範囲と値 | `D.pt`（補完） |
| 6）手術 | 対応コード(F列), 手術1〜5（名称・Kコードの対、複数列は「＋」組み合わせ） | `D.si`, `D.sl`, `D.cn` |
| 7）手術・処置等１ | 対応コード(C列), 手術との組み合わせ条件(E列), コード1・2 | `D.p1`, `D.pc`, `D.cn` |
| 8）手術・処置等２ | 対応コード(C列), コード1・2 | `D.p2`, `D.cn` |
| 9）定義副傷病名 | 対応コード, 副傷病フラグ(1/2/3), ICDコード | `D.sd` |
| 10-1〜10-4）重症度等 | 条件名, 値・ラベル | `D.sv` の `name`・補完ラベル |
| 11）診断群分類点数表 | 診断群分類番号, 傷病名, 手術名, 処置等1・2, 副傷病, 重症度等, 日数Ⅰ〜Ⅲ, 点数Ⅰ〜Ⅲ | `D.dpc`, `D.lb`, `D.br`, `D.pt`, `D.sv` |
| 12）変換テーブル | 診断群分類番号, 包括フラグ, 手術・処置等1・処置等2・副傷病の対応コード | `D.dpc[2]`, `D.cv`（対応コード≠DPC桁となる縮約の写像） |
| 13）出来高算定手術等コード | 区分コード, 手術/検査コード, 名称, （薬剤名称・対象患者の小表） | `D.dk`, `D.dx` |
| 14）CCPM対応 | 診断群分類番号, CCPM支払分類 | `D.cc` |
| ダミーコード一覧 | 先頭セル「令和八年度仕様」 | `D.meta.label` |

全シート共通で「変更区分」「有効期間（開始日・終了日）」「更新日」列を解釈します（基準日 = `--as-of` または全シートの最新日付）。

## 7. トラブルシューティング

| 症状 | 原因 | 対処 |
|------|------|------|
| `シート「…」が見つかりません` | シート名の変更 | `scripts/generate-data.mjs` の `readSheet(wb, "…")` のキーワードを新名称に合わせる |
| `条件ラベルなし: <code>` | 点数表の傷病名が「分類名（条件）」形式でなく、年齢等シートにも該当がない | 点数表・年齢等シートの該当行を確認。必要なら `COND_FORMAT` を追加 |
| `重症度ラベルなし: <code>` | 14桁目の値に対応する重症度等ラベルがない | 点数表「重症度等」列と 10-x シートを確認 |
| `分岐ラベルの欠落 N 件` | 点数表の手術名・処置等名が空 | 該当DPCの点数表行を確認 |
| `日数が不正` / `点数Ⅱが0` | 点数表の値が想定外（「-」以外の文字列など） | 該当行を確認。期間Ⅱなし（「-」）は正常として扱われる |
| `npm run validate:data` が FAIL | `src/data.js` が古い、または `database/` に旧Excelが残っている | 旧Excelを削除し `node scripts/generate-data.mjs` を再実行 |
| 画面が真っ白 | `src/data.js` の構文エラー・キー不足 | `node -e "import('./src/data.js').then(m=>console.log(Object.keys(m.D)))"` で確認 |
| 別名で薬剤が見つからない | `drug-aliases.json` のコードが現行の処置等2に無い（`[NOTE]` に表示） | 新しいダミーコードに付け替える |

### DPC制度の構造的変更があった場合

以下のような変更は `src/utils.js` やUIの改修が必要です（本手順書の範囲外）。

| 制度変更の例 | 影響箇所 |
|-------------|---------|
| DPCコードが14桁から変更 | `utils.js` の桁位置（`toResult`, `getCondLabel`, `getSevInfo`）、生成スクリプト |
| 期間が3段階から変更 | `D.dpc` の配列構造、`calcTotal`、`SimChart`、`CompareModal` |
| 新しい分岐軸の追加（処置等3 等） | `D.br`, `utils.js`, `SuggestRightPanel`, 生成スクリプト |
| 副傷病フラグの追加 | 生成スクリプト `SD_FLAG_KEY`, `getSubdiagICDs` |
